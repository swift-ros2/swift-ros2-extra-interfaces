# swift-ros2-extra-interfaces

ROS 2 interfaces from outside [common_interfaces](https://github.com/ros2/common_interfaces)
(`control_msgs` and `moveit_msgs`, with the `object_recognition_msgs` and `octomap_msgs` types
`moveit_msgs` uses) for Swift, generated by `swift-ros2-gen` from the upstream IDL. One Swift
module per ROS package; depends only on
[swift-ros2-rosidl](https://github.com/swift-ros2/swift-ros2-rosidl) and
[swift-ros2-common-interfaces](https://github.com/swift-ros2/swift-ros2-common-interfaces), so
it downloads no native frameworks. Publish, subscribe, call and send goals with
[swift-ros2](https://github.com/swift-ros2/swift-ros2).

```swift
// swift-tools-version: 5.9
// The interfaces need macOS 13, iOS 16, Mac Catalyst 16 or visionOS 1, like swift-ros2.
platforms: [.iOS(.v16), .macOS(.v13), .macCatalyst(.v16), .visionOS(.v1)],
dependencies: [
    .package(url: "https://github.com/swift-ros2/swift-ros2-extra-interfaces.git", from: "1.1.0"),
    // swift-ros2 does the publishing, subscribing, calls and goals. 3.1.0 or later sends the
    // layout and hash of the distribution it runs against (see Distributions).
    .package(url: "https://github.com/swift-ros2/swift-ros2.git", from: "3.1.0"),
],
// …
.product(name: "ControlMsgs", package: "swift-ros2-extra-interfaces"),
.product(name: "MoveitMsgs", package: "swift-ros2-extra-interfaces"),
.product(name: "SwiftROS2", package: "swift-ros2"),
```

| Module | ROS package | Types it holds | Distributions |
| --- | --- | --- | --- |
| `ControlMsgs` | `control_msgs` | `GripperCommand` (message), `GripperCommandAction` (action, with `Goal`, `Result` and `Feedback`) | Humble, Jazzy, Kilted, Lyrical |
| `MoveitMsgs` | `moveit_msgs` | `ServoStatus` (message), `ServoCommandTypeSrv` (service, with `ServoCommandTypeRequest` and `ServoCommandTypeResponse`); `MoveGroupAction` (action, with `Goal`, `Result` and `Feedback`) and the messages it reaches: `AllowedCollisionEntry`, `AllowedCollisionMatrix`, `AttachedCollisionObject`, `BoundingVolume`, `CartesianPoint`, `CartesianTrajectory`, `CartesianTrajectoryPoint`, `CollisionObject`, `Constraints`, `GenericTrajectory`, `JointConstraint`, `LinkPadding`, `LinkScale`, `MotionPlanRequest`, `MoveItErrorCodes`, `ObjectColor`, `OrientationConstraint`, `PlanningOptions`, `PlanningScene`, `PlanningSceneWorld`, `PositionConstraint`, `RobotState`, `RobotTrajectory`, `TrajectoryConstraints`, `VisibilityConstraint`, `WorkspaceParameters` | Jazzy, Kilted, Lyrical |
| `ObjectRecognitionMsgs` | `object_recognition_msgs` | `ObjectType` (message, used by `CollisionObject`) | Jazzy, Kilted, Lyrical |
| `OctomapMsgs` | `octomap_msgs` | `Octomap`, `OctomapWithPose` (messages, used by `PlanningSceneWorld`) | Jazzy, Kilted, Lyrical |

The standard types these hold (`std_msgs/Header`, `geometry_msgs/Pose`,
`sensor_msgs/JointState`, `trajectory_msgs/JointTrajectory`, `shape_msgs/SolidPrimitive`, …)
come from swift-ros2-common-interfaces: add its `StdMsgs`, `GeometryMsgs`, `SensorMsgs`,
`ShapeMsgs` or `TrajectoryMsgs` product to build them.

A module holds a subset of its ROS package: the interfaces listed above, plus the generated
action wrapper types (such as `GripperCommand_SendGoal_Request` and
`GripperCommand_FeedbackMessage`), and nothing else, not the whole upstream package. Requests
for more types are welcome; open an issue.

`moveit_msgs` added the Servo interfaces in 2.6.0 (Jazzy), so `MoveitMsgs` starts at Jazzy;
Humble's `moveit_msgs` 2.2.3 has neither, and `MoveGroupAction` is generated for the same
distributions. Rolling uses the Lyrical definitions. There is no umbrella product: add each
module you use separately.

There are no hand-written helpers; the generated constants are the API:

- `ServoCommandTypeRequest.JOINT_JOG` / `TWIST` / `POSE` are 0 / 1 / 2.
- `ServoStatus.INVALID`, `NO_WARNING`, `DECELERATE_FOR_APPROACHING_SINGULARITY`,
  `HALT_FOR_SINGULARITY`, `DECELERATE_FOR_LEAVING_SINGULARITY`, `DECELERATE_FOR_COLLISION`,
  `HALT_FOR_COLLISION` and `JOINT_BOUND` are -1 to 6.
- `MoveItErrorCodes.SUCCESS` is 1, `UNDEFINED` 0, `FAILURE` 99999, and the failures are
  negative (`PLANNING_FAILED` -1, `TIMED_OUT` -6, `INVALID_GROUP_NAME` -15,
  `NO_IK_SOLUTION` -31, …), as in `moveit_msgs/msg/MoveItErrorCodes`.

### Distributions

Lyrical's `moveit_msgs` 2.7.2 adds `float64 smoothness_level` at the end of
`MotionPlanRequest`; Jazzy (2.6.0) and Kilted (2.7.1) do not have it. It is the only difference
among the distributions in these modules. `MotionPlanRequest.smoothnessLevel` is a plain
property that is encoded only for Lyrical and later (Rolling included); on Jazzy and Kilted it is
not sent, and a received request decodes it as `0.0`. The generated code checks
`encoder.schemaDistro >= .lyrical`; compare `context.distro >= .lyrical` the same way to know
whether a value you set is sent.

Because of that field, `MotionPlanRequest`, `MoveGroupAction.Goal`, `MoveGroup_SendGoal_Request`
and the SendGoal service have one type hash on Jazzy and Kilted and another on Lyrical and
Rolling: `MotionPlanRequest.typeInfo(for:)` and `MoveGroupAction.typeInfo(for:)` return the one
of a distribution, and `typeInfo` is the Jazzy one. Every other type has one hash.

swift-ros2 sends the layout and the hash of the distribution it runs against only from 3.1.0,
which asks generated types for `typeInfo(for:)` and creates codecs for the context's
distribution. With swift-ros2 3.0.x (which SwiftPM can still resolve with this package), a
MoveGroup goal goes out with the Jazzy layout and hash on every distribution, which Lyrical's
`move_group` does not match over Zenoh (the key expression carries the hash) and cannot decode
over DDS (the request is 8 bytes short). Depend on swift-ros2 `from: "3.1.0"`.

## Usage

With swift-ros2 3.0, these calls are `async throws`. This switches MoveIt Servo to Twist
commands, watches its status, then closes a gripper through its `GripperCommand` action server:

```swift
import ControlMsgs
import MoveitMsgs
import SwiftROS2

let context = try await ROS2Context(
    transport: .zenoh(locator: "tcp/192.168.1.100:7447", domainId: 0), distro: .jazzy)
let node = try await context.createNode(name: "arm_teleop")

// moveit_msgs/srv/ServoCommandType
let client = try await node.createClient(
    ServoCommandTypeSrv.self, name: "/servo_node/switch_command_type")
try await client.waitForService(timeout: .seconds(5))
let response = try await client.call(
    ServoCommandTypeRequest(commandType: ServoCommandTypeRequest.TWIST), timeout: .seconds(2))
print("switched: \(response.success)")

// moveit_msgs/msg/ServoStatus
let status = try await node.createSubscription(ServoStatus.self, topic: "/servo_node/status")
let watcher = Task {
    for await message in status.messages where message.code == ServoStatus.HALT_FOR_COLLISION {
        print("collision: \(message.message)")
    }
}

// control_msgs/action/GripperCommand
let gripper = try await node.createActionClient(
    GripperCommandAction.self, name: "/panda_hand_controller/gripper_cmd")
let handle = try await gripper.sendGoal(
    .init(command: GripperCommand(position: 0.04, maxEffort: 20)))
let result = try await handle.result()
print("gripper: \(result)")
watcher.cancel()
await context.shutdown()
```

Use swift-ros2's wire transports: `.zenoh(locator:domainId:)`, `.ddsMulticast(domainId:)` or
`.ddsUnicast(peers:domainId:)`. On the RCL backend these types have no
bundled type support. Creating a client or server for `ServoCommandTypeSrv`,
`GripperCommandAction` or `MoveGroupAction` throws `TransportError.unsupportedFeature` on any RCL
graph. A publisher or subscription for a message type throws only where RCL speaks Zenoh
(`rmw_zenoh_cpp`).

### MoveGroup

This sends a joint-space goal to `move_group` (plan and execute), prints its feedback, and
cancels it if it is still running after 10 seconds. `move_group` serves the action as
`/move_action`; the joint names are those of the MoveIt Panda demo.

```swift
import MoveitMsgs
import SwiftROS2

let context = try await ROS2Context(
    transport: .zenoh(locator: "tcp/192.168.1.100:7447", domainId: 0), distro: .lyrical)
let node = try await context.createNode(name: "arm_planner")

// moveit_msgs/action/MoveGroup
let moveGroup = try await node.createActionClient(MoveGroupAction.self, name: "/move_action")
try await moveGroup.waitForActionServer(timeout: .seconds(5))

// One JointConstraint per joint: the target position and how far from it counts as reached.
let target: [(joint: String, position: Double)] = [
    ("panda_joint1", 0), ("panda_joint2", -0.785), ("panda_joint3", 0), ("panda_joint4", -2.356),
    ("panda_joint5", 0), ("panda_joint6", 1.571), ("panda_joint7", 0.785),
]
let request = MotionPlanRequest(
    goalConstraints: [
        Constraints(
            jointConstraints: target.map {
                JointConstraint(
                    jointName: $0.joint, position: $0.position, toleranceAbove: 0.01, toleranceBelow: 0.01,
                    weight: 1)
            })
    ],
    groupName: "panda_arm",
    numPlanningAttempts: 5,
    allowedPlanningTime: 5,
    maxVelocityScalingFactor: 0.2,
    maxAccelerationScalingFactor: 0.2)
// planOnly: false plans and executes; true only plans.
let handle = try await moveGroup.sendGoal(
    MoveGroupAction.Goal(request: request, planningOptions: PlanningOptions(planOnly: false)))

let feedback = Task {
    for await update in handle.feedback { print("move_group: \(update.state)") }
}
let deadline = Task {
    try await Task.sleep(for: .seconds(10))
    try await handle.cancel()
}
switch try await handle.result() {
case .succeeded(let result) where result.errorCode.val == MoveItErrorCodes.SUCCESS:
    print("done, planned in \(result.planningTime) s")
case .succeeded(let result):
    print("move_group error \(result.errorCode.val): \(result.errorCode.message)")
case .aborted(let reason):
    print("aborted: \(reason ?? "")")
case .canceled:
    print("canceled")
}
deadline.cancel()
feedback.cancel()
await context.shutdown()
```

## Upstream IDL and regeneration

The package has no submodules and ships no IDL: the generated Swift under
`Sources/<Module>/Generated/` is committed, so resolving this package downloads only Swift
sources. `idl.lock` pins one upstream commit per repository and distribution
(`<name> <url> <distribution> <commit>`), and `Scripts/fetch-idl.sh` (from swift-ros2-rosidl)
downloads exactly those commits into the gitignored `.idl/` cache, verifying each SHA.

| `idl.lock` repository | Packages | Role |
| --- | --- | --- |
| `control_msgs` | `control_msgs` | emitted (`--input`), Humble to Lyrical |
| `moveit_msgs` | `moveit_msgs` | emitted (`--input`), Jazzy to Lyrical |
| `object_recognition_msgs` | `object_recognition_msgs` | emitted (`--input`), Jazzy to Lyrical |
| `octomap_msgs` | `octomap_msgs` | emitted (`--input`), Jazzy to Lyrical |
| `common_interfaces` | `std_msgs`, `geometry_msgs`, `sensor_msgs`, `shape_msgs`, `trajectory_msgs` | dependency-only (`--dependency`); its types live in swift-ros2-common-interfaces |
| `rcl_interfaces` | `builtin_interfaces` | dependency-only (`--dependency`); its types live in swift-ros2-rosidl |
| `unique_identifier_msgs` | `unique_identifier_msgs` | dependency-only (`--dependency`), for the action wrappers |

`control_msgs`, `moveit_msgs`, `object_recognition_msgs` and `octomap_msgs` are pinned at the
release tag that rosdistro lists for the distribution (`distribution.yaml`, `release: version`),
which is what `apt` installs and what the oracles check against. `common_interfaces`,
`rcl_interfaces` and `unique_identifier_msgs` are pinned at the commits
swift-ros2-common-interfaces generates from, and passed for every distribution it is generated
for (Humble to Lyrical), so the hashes here include the same dependency types as the Swift types
they refer to. The generator reads only the interfaces named in `--types`
(`Scripts/generator-args.sh`), so the rest of each package is never parsed.

`Scripts/generator-args.sh` prints the generator arguments; `Scripts/regenerate.sh` fetches the
IDL, runs the `swift-ros2-gen` of the rosidl version in `Package.resolved` and rewrites the
generated sources. To move to a newer upstream release, change the commit on the line
(`git ls-remote --tags <url> <version>`), run `Scripts/regenerate.sh` and commit `idl.lock`
together with the regenerated sources.

## Verification

- CI fails when the committed sources differ from what `idl.lock` produces. It builds on macOS,
  Linux, Windows and Android, builds DocC for every module, checks that resolving the package
  downloads no binaries, and compares the public API with the latest 1.x release.
- The unit tests pin each ROS name, field label and constant, the CDR round trip of every type,
  and the type hash and wire shape of the types.
- The oracle workflow runs swift-ros2-rosidl's reusable `interface-oracles.yml` on every pull
  request for Jazzy and Lyrical, and weekly for Kilted and Rolling. It compares every RIHS01
  type hash with the real `ros-<distro>-control-msgs`, `ros-<distro>-moveit-msgs`,
  `ros-<distro>-object-recognition-msgs` and `ros-<distro>-octomap-msgs` packages, and every CDR
  sample, encoded with that distribution's layout, with `rclpy`. The weekly run also signals when a release on the ROS build
  farm differs from the pin.
